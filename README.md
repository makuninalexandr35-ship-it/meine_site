# Персональное digital-портфолио

Статический сайт на Astro и TypeScript. Собирается в HTML/CSS/JavaScript и подходит для размещения на обычном хостинге. Сервер и форма сбора заявок сейчас намеренно не используются: сайт не обрабатывает персональные данные.

## Запуск

```bash
npm install
npm run dev
npm run build
npm run preview
```

После `npm run build` готовый статический сайт находится в `dist/`.

## Где менять контент

- Контакты, название, домен и SEO: `src/data/site.ts`.
- Реальные проекты и их метаданные: `src/data/projects.ts`.
- Логотип: `src/assets/Logotip.webp` (исходник остаётся в корне репозитория).
- Фото и скриншоты проектов: `public/media/photos/<project-slug>/`.
- Будущие видео: `public/media/videos/`.
- Текст главной страницы: компоненты в `src/components/`.

## Как добавить проект

1. Создайте папку `public/media/photos/<project-slug>/` и добавьте обложку, например `cover.webp`.
2. Добавьте объект в `src/data/projects.ts` и укажите пути вида `/media/photos/<project-slug>/cover.webp`.
3. Заполните только подтверждённые сведения и смените `published` на `true`.
4. При необходимости добавьте `gallery` и `liveUrl`.
5. Запустите `npm run build`.

Карточка на главной, страница `/project/<project-slug>/`, навигация между кейсами, метаданные и URL в sitemap создадутся автоматически.

## Перед публикацией

Замените TODO-значения в `src/data/site.ts`: имя/бренд, `siteUrl`, Telegram и email. Затем поменяйте `site` в `astro.config.mjs` и строку `Sitemap` в `public/robots.txt` на этот же домен.

Для обычного хостинга загрузите содержимое `dist/` в публичную директорию сайта и настройте домен на неё. Для корректной 404-страницы у хостинга должен быть включён fallback на `404.html`.

## Автопубликация на Beget

В `.github/workflows/deploy.yml` настроена автопубликация после каждого `git push` в ветку `main`. Перед первым запуском в репозитории GitHub нужно добавить Secrets:

- `BEGET_FTP_SERVER` — адрес FTP-сервера Beget;
- `BEGET_FTP_USERNAME` — отдельный FTP-пользователь для публикации;
- `BEGET_FTP_PASSWORD` — пароль этого пользователя.

Workflow собирает сайт и загружает только содержимое `dist/` в `/aleksandrmakunin.ru/public_html/`. Пароль не хранится в коде и не публикуется в Git.

## Персональные данные и будущие заявки

Текущая версия содержит только Telegram и `mailto:` ссылки, поэтому персональные данные через сайт не собираются и не хранятся. Если позднее будет добавлена форма, не сохраняйте заявки в браузере, аналитике или стороннем зарубежном сервисе. Нужен серверный endpoint, расположенный в России, с обработкой у российского провайдера (например, Badgeit — после уточнения его API и условий хранения), минимизацией данных и удалением данных сразу после успешной доставки. Реализацию формы нельзя безопасно завершить без реального российского провайдера, его API и политики хранения.
